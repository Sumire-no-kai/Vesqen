# M4 开发清单：验证矩阵与公开 Beta

2026-09-08。范围与完成条件以 [PRD 的 M4 章节](PRD.md) 为准，视觉与交互遵循 [DESIGN.md](../DESIGN.md)。本文件记录开发任务，不代表这些功能或验收已经完成。

## 当前状态与阶段边界

**可以开始 M4 软件开发与验证准备；M3 尚未完成。** [M3 未完成项](M3_IMPLEMENTATION_PLAN.md)中的 Library 实际修复、双机对照、真实 DAC、旧系统和交付门禁继续保留。M4 不扩展为 native 播放内核、自定义 USB 驱动或 M5 的高级播放功能。

用户目前没有 DAC，外部 bit-perfect 验证等待设备；Bluetooth 按此前要求暂缓。长时间测试继续暂缓，可以准备脚本和验收步骤，但不自动启动。优先复用现有遥测、诊断导出、测试工具和文档，不预设新后端、新数据库或独立页面。

## 主要任务

| 编号 | 任务 | 主要交付物与验收点 | 当前可开展范围 |
| --- | --- | --- | --- |
| M4-01 | 验证记录与兼容矩阵 | 为手机型号、Android/ROM、DAC/固件、源/输出格式、应用版本及 APK 哈希建立可追溯记录；关联方法、时间、结果、限制和证据位置。区分通过、失败、未测试、缺少设备及用户暂缓，保留失败历史。 | 可立即整理记录结构、校验规则、报告脚本和已有证据；不把旧版本通过自动继承给新组合。 |
| M4-02 | 测试音源与外部验证流程 | 准备可合法使用或自行生成的已知测试向量，记录校验和、采样率、位深、声道和预期结果；形成设备位准确测试或合适数字采集的复现步骤。明确证据在哪个信号位置取得。 | 音源生成/校验和流程可以先做；真实 DAC 测试或数字采集等待设备。DAC 采样率显示、听感或模拟录音不能单独证明逐样本 bit-perfect。 |
| M4-03 | 声明与证据关联 | 审查播放器、Chain、诊断及发布说明中的声明与验证记录是否一致；只有精确组合的有效外部证据才支持 VERIFIED。版本或组合变化时重新判定证据适用性；缺失、失配和不可用原因可解释。导出及公开记录保留隐私过滤。 | 可先做匹配逻辑、失配/缺失回归和现有展示入口的衔接；不增加可随意勾选 VERIFIED 的入口。 |
| M4-04 | 稳定性、中断与资源检查 | 准备长时播放/诊断、切歌、后台、锁屏、音频焦点及来电恢复、设备拔插和服务恢复矩阵；记录错误、资源释放和测试前后状态，保护用户曲库与设置。 | 可做不依赖外设的短测及脚本准备；真实路由依赖设备，来电验证需要对应测试条件；长时间运行继续暂缓。 |
| M4-05 | 性能基线与界面验收 | 建立启动、Library/Chain 滑动、CPU/内存、有效放电功耗、温升及安装体积基线；记录实际刷新率和构建类型。补齐中英文、窄屏/横屏/大字、不同窗口、TalkBack、对比度与减少动效；修复已知英文会话进度标签省略。 | 可先做界面修复、静态/自动化检查和可用设备短测；Library 根因与修复仍记在 M3-R1。折叠/旧机/高刷新率等缺失组合保持未验证，完整语音体验不能仅凭语义树宣布通过。 |
| M4-06 | Beta 发布准备 | 汇总阻断缺陷与已知限制，准备版本说明、支持范围、安装/升级/数据保留检查、发布包身份及签名配置核验、隐私说明和发布检查清单；每项公开音频声明关联证据。 | 可立即准备和检查；不改写既有签名/凭据，不因完成文档而自动发布。最终交付还需对应构建、CI 和实机验收。 |

发布诊断硬门禁：Debug/Internal 可提供应用私有、可恢复、隐私清理后的诊断录制；Profile
和公开 Release 必须在构建期装配为关闭状态，不显示任何日志或诊断录制入口，不启动采样，
也不创建诊断文件。该约束不能只依赖隐藏界面或可被恢复的运行时偏好。

## 建议实施顺序

1. M3 当前软件候选已通过 PR #21 合并，未完成验收项继续保留；后续代码工作使用按产品目的命名的 `feature/m4-…` 分支，按仓库流程交付。
2. 先完成 M4-01 的记录结构与校验，再准备 M4-02 的测试音源和工具；复用已有原始证据，不重复采集已经适用的结果。
3. 推进 M4-03 的证据匹配及展示衔接，同时修复 M4-05 已知的英文会话标签省略并补回归。
4. 在可用设备上做 M4-04/M4-05 的短时回归、适配与性能采集；M3-R1 的 Library 调查并行继续。
5. 准备 M4-06 发布材料。设备到位或用户恢复长时测试安排后，再执行对应矩阵，补齐证据并处理发现的问题。

## 完成条件

- [ ] M4-01 至 M4-06 的交付物和适用验收完成；缺失设备、未执行项目和限制有明确记录。
- [ ] 至少一个精确手机/ROM/DAC/格式/应用版本组合取得有效外部证据，达到 BIT-PERFECT VERIFIED。
- [ ] M3 遗留门禁和相关 M2 验收逐项关闭或明确保留；不能通过更换阶段名称宣称已经完成。
- [ ] Beta 阻断缺陷清零，已知限制公开，公开音频声明都能链接到对应证据。
- [ ] 最终发布候选完成适用的构建、回归、升级/数据保留及交付检查，各类证据分开报告。

没有 DAC 时可以推进软件并准备受限 Beta，但**不满足原定 M4 全部完成条件**。是否实际发布受限 Beta、其功能与声明范围，需要在可审阅的候选和证据明确后决定；本清单不构成发布动作。

- M4-01：已实现严格 schema、不可变组合身份、私有持久化、结果枚举、精确匹配与签名 registry 导入；失败记录的外部归档和真实设备矩阵仍按验收文件累积。
