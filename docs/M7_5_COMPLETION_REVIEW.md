## 深度代码复核

逐项检查了入口、调用者、状态发布、会话传输、原生会话控制、清理和对应测试，而非只检查新增行。

| 检查面 | 核对的边界 |
| --- | --- |
| 标签解析 | 缓冲区 mark/reset、EOF、恰好 64 KiB 与超限、未知非零字节、FLAC/ADTS/MPEG 识别、已有标签保留 |
| 长队列 | 通知控制器与应用控制器的权限区分、初始化连接顺序及取消、首次 2,010 首入队、100/101 边界和恢复、监听器注册/释放、固定音量会话命令保留 |
| 首次使用与固定输出 | 未确认前没有接口接管或音频流、取消后保持停止、代次和观察时间校验、当前 period、换设备和清空队列后的旧确认 |
| 硬件控制 | 可写主音量失败关闭、逐声道控制继续拒绝、固定输出不写音量或解除静音、UAC2 时钟仍在 alternate setting 之前设置并读回 |
| 生命周期 | 暂停/等待不冒充接管、确认等待结束本次媒体按键启动义务、已有恢复记录和清理屏障保留 |
| 证据与隐私 | 未检查设备能力时不声明 AVAILABLE、ACTIVE/VERIFIED 门槛保持、计数来源与不可用状态、USB 线路指标仍为 LOCAL_ONLY |

复核中修正的问题：

1. 首次独占说明发生在授权和描述符检查之前，不能发布 `BIT-PERFECT AVAILABLE`。等待播放或取消时保留 `SYSTEM MIXED`；实际播放请求等待确认时为 `BIT-PERFECT REQUESTED`。回归检查这两个声明边界。
2. 固定音量 DAC 的设置说明不能沿用“音量条和手机音量键可调节”的文字。现在明确说明由 DAC 或功放调节，四语言界面测试覆盖。
3. 确认提示结束本次 Play 请求而没有出声时，也要结清媒体按键启动的前台服务义务。新增回归，不把提示当成播放成功。
4. 固定输出接入 UAC2 时保留时钟配置；新增只读音量 UAC2 用例，检查时钟设置顺序及未写音量。
5. #302 原先在通知控制器连接前仍可能发布一次长队列。现在其他控制端的连接等待 `onPostConnect`，此时 Media3 已应用通知控制器的命令；第一个入队或媒体按键恢复也走同一上限。单个连接取消不影响共享初始化，服务销毁取消等待。沿用框架的会话注册入口，保留未获准媒体按键启动的原有前台服务行为。

启动顺序按固定版本 [Media3 1.11.0 的连接实现](https://github.com/androidx/media/blob/1.11.0/libraries/session/src/main/java/androidx/media3/session/MediaSessionImpl.java)和[服务注册实现](https://github.com/androidx/media/blob/1.11.0/libraries/session/src/main/java/androidx/media3/session/MediaSessionService.java)核对。将连接策略临时恢复为原来的立即接受后，三项启动回归按预期失败；恢复修复后，四项启动测试全部通过。真机单项也通过：首次入队 2,010 首，监听全部平台队列回调，检查应用完整队列及缩回 100 首、增至 101 首和再次恢复。

测试本身也作了必要修正：Android 弹窗需要真实应用语言和系统字号配置；音量无障碍测试按资源读取当前语言；来自应用界面的播放测试使用空白前台宿主，不引入应用 UI 控制器或 Compose 测试时钟。Android 15 的焦点前提见 [Android 文档](https://developer.android.com/media/optimize/audio-focus)。
